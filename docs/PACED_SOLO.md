# One clue at a time

New solo cases opened by the client use paced play. There is no case countdown. Witnesses wait until the human inspects their first record, then perform one search only when explicitly asked. One bot moves at a time, capped at 90 world units per second (human maximum 230), and pauses briefly at the source. One search recovers one physical record and shares at most one relevant memory. No timed testimony flood, automatic board draft, motive disclosures or automatic final votes run in this mode.

Reading a clue, memory, board, map, settings, goal or More panel pauses solo progress. Hidden tabs and disconnects also stop the search; reconnect starts paused until the client reports readiness. An active search and its route survive a checkpoint. Three recovered records open the backup sources without a timer. Human submission supplies the scripted partners’ votes; the human owns when the case ends. Nightmare is optional and initially unchecked. In paced solo its pursuit also pauses while reading. Multiplayer timing and human movement speed are unchanged.

The opening gives one instruction and the world highlights the next accessible personal record. The initial toolbar is empty. Clues appear after the first record, and Build answer appears after records cover all six events. The clue notebook shows one record’s known facts; full prose is collapsed. Matching memories can be compared without betting controls. The tutorial keeps one instruction visible, with optional explanations. Board fact grids, statuses and linked-source lists are folded into per-row Details.

The HTTP solo request uses `paced_solo: true`; omitted/false preserves the earlier scripted demo for existing clients. Rooms without the persisted `solo_paced` flag retain their original rules. Start a new solo case for the new experience. Authenticated `solo_step` requests one search and `solo_reading` reports reading/visibility state. These commands cannot control a multiplayer room. Only one route is planned per requested search, off the event loop; scenery and rendering use the existing caches/context.

Verification: six pacing tests cover all three maps, first-clue gating, speed, one active bot, pauses, disconnection/reconnection, manual completion, persistence/rematch, and multiplayer isolation. The full backend suite passes 110 checks. The client suite passes 94 checks. Local real-action campus TGXEG recovered 16 records through 12 requested searches, stayed outside the automatic script, paused/reconnected, submitted a 100% answer, saved replay TGXEG-1 and rematched in 272 seconds with zero automatic reconnects. This is functional verification; fresh-player understanding still requires a human playtest.
